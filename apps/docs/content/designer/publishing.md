# Preview and publish

What you draw is a draft: buyers never see it, and events cannot use it, until you publish. At the end of this page you will have looked at the chart as buyers will, published it, and created an event from it.

## Preview

1. Choose **Preview** at the top right. The chart opens as a buyer's seat map.
2. Choose the width to look at: **Phone**, **Tablet** or **Desktop**. Most buyers use a phone, so check that one first: can you find the stage, tell the categories apart, and read the row letters when you zoom in?
3. Choose a **Sample state**: **Empty house**, **Half sold** or **Nearly sold out**. The sales are made up, so you can see how taken seats look among free ones.
4. Choose a seat to see what a buyer sees: its label and its category.
5. Close the preview with the cross at the top right.

![The preview at phone width, half sold](../images/designer-preview.webp)

Nothing in the preview is saved or sold. The small "Development licence" mark in a corner of the map appears while your Cavea server has no licence; it goes when one is installed.

## Publish

Publishing turns the draft, as it is now, into a version of the chart: a fixed copy, numbered 1, 2, 3, that events are created from. It needs a chart without errors ([Check the chart](checking.md)), and the role of owner, admin or editor.

1. Choose **Publish** at the top right.
2. The message says what is published now, if anything, and how many seats this draft has.
3. Choose **Publish**. When it is done it says **Published version 1: 136 seats.** For a later version it also says how many seats it adds or removes.
4. Close the message.

![The Publish message after publishing version 1](../images/designer-published.webp)

Publishing also takes a small picture of the chart for the console's **Charts** list. If that picture could not be made, the message says "published without a picture"; the version is published all the same.

Publishing what is already published changes nothing: the message says the draft is the published version.

## Versions and events

An event is created from one version of a chart and keeps it: publishing the chart again later does not change an event that is already on sale. This is on purpose. A seat a buyer has bought must not move, change its label or change its price level because someone edited the chart afterwards.

To see the versions, go back to the console (the **Menu**'s **Back to console**) and open the chart from **Charts**:

![The chart's Versions tab, with version 1 marked current and its Create event button](../images/designer-versions.webp)

- **Versions** lists every version with when it was published and its seats. **Current** marks the one new events use.
- **Create event** beside a version makes an event from it.
- **Events** lists the events using the chart, and which version each has.

So: change and publish the chart as often as you need before events go on sale. After that, a change you publish applies to the events you create from then on. An event already on sale keeps its version; to sell it from a new version, your box office creates a new event from that version.

> **Note** If you edit the chart while a large chart is publishing, the message may say "The draft changed elsewhere before it was published; nothing was published." Nobody else changed it: your own edit arrived first. Publish again.
